# Diffcast

Paid daily two host tech and AI news podcast for developers, personalized by each listener's interests (topics with an optional take and note) with their stack as one extra signal, plus a planned remote MCP server for agent context sync. Tagline in use (proposed 2026-11-16): "What changed in your corner of tech since yesterday." Spun out of the podcast feature in `~/Development/cvzx`. Name Diffcast, chosen 2026-11-16; domain diffcast.fm (bought at Porkbun 2026-11-16; diffcast.dev is taken).

## MCP and OAuth

- Remote MCP server at `/api/mcp` (`mcp-handler` 2.3.1 on `@modelcontextprotocol/server` 2.4.0, the SDK v2 that mcp-handler 2 requires, stateless Streamable HTTP, spec 2026-07-28 with the 2025 fallback). `withMcpAuth` with `required: true` and scope `diffcast`: without a valid token it answers 401 with `WWW-Authenticate: Bearer error="invalid_token", ..., scope="diffcast", resource_metadata="<origin>/.well-known/oauth-protected-resource"`. Then a per grant throttle (120 calls a minute per instance, 429). Every origin derives from the request host (`requestOrigin`), so `https://diffcast.fm` and a local dev server each act as their own issuer and resource; tokens are bound to the resource they were issued for.
- Tools (`src/lib/mcp/`): `push_context`, `list_context`, `clear_context`, `get_interests`, `set_interests`, `add_interest`, `remove_interest`, `get_schedule`, `set_days`, `get_latest_episode`, `list_episodes`. Each runs for the token's listener only, and only while that listener is served (otherwise an `isError` result, the token stays valid). Inputs are zod schemas in `rules.ts` (project `[a-z0-9._/-]{1,80}`, lowercased; packages must look like npm, PyPI, crates, Go module or RubyGems names, optional `ecosystem:` prefix; topics and summary plain one line words). Outputs are `structuredContent` plus a one line text. Episodes never carry audio urls or turns; their link is `<origin>/account`. Interest edits go through `parseInterestsEditor` and `saveInterests`. `push_context` upserts `work_context` by (listener, project), expiry 30 days, capped at 60 calls a listener a day in `mcp_usage` (atomic upsert that refuses past the cap).
- Authorization server, all in this app:
  - Metadata: `/.well-known/oauth-protected-resource` and the path suffixed `/.well-known/oauth-protected-resource/api/mcp` (RFC 9728), `/.well-known/oauth-authorization-server` (RFC 8414: S256 only, `authorization_code` and `refresh_token`, public clients, scope `diffcast`, `client_id_metadata_document_supported: true`, `authorization_response_iss_parameter_supported: true`).
  - Clients: Client ID Metadata Documents (the spec's SHOULD; a `https://` client id with a path is fetched by `src/lib/oauth/fetch-metadata-document.ts` over `node:https` with a DNS lookup that refuses private, loopback and special addresses at connect time (IPv6 must also be inside 2000::/3 global unicast), port 443 only, no redirects, a 5 s total deadline that destroys the request, 10 KB, cached per Cache-Control between 5 minutes and a day; a failed client id is not fetched again for 5 minutes and each IP may trigger 10 fetches per 10 minutes, both per instance in `src/lib/oauth/throttles.ts`) and Dynamic Client Registration at `POST /oauth/register` (deprecated by the spec, kept for clients that need it; public only, redirect uris https or http on localhost, 127.0.0.1 or [::1], plus exactly `cursor://anysphere.cursor-mcp/oauth/callback` for registered clients only, because Cursor builds still register it beside `https://www.cursor.com/agents/mcp/oauth/callback` and `http://localhost:8787/callback`, the callbacks its docs list; 10 registrations an hour per IP). Client rules in `src/lib/oauth/client-metadata.ts`.
  - `GET /oauth/authorize` (`checkAuthorizeRequest` in `src/lib/oauth/authorize-request.ts`): unknown client or unregistered redirect uri shows an error page and never redirects; other errors (response_type, PKCE S256 required, `resource` must be `<origin>/api/mcp` when present, scope) redirect back with `error`, `state` and `iss`. Needs the listener session: without one it goes to `/oauth/continue`, which remembers the return path and sends them to `/signin`. A served listener sees the consent page (`consent-view.tsx`: a registered client's name is shown as self declared, "an agent that calls itself ...", a metadata document client's name with its publishing domain; the redirect host in large type, or "the Cursor app" for its app callback; the signed in email; a warning for loopback and app callbacks; framing denied in `next.config.ts`). Allow (a server action that re-validates everything) stores a code hash, 10 minutes, bound to client, redirect uri, challenge, listener and resource, and redirects with `code`, `state`, `iss`.
  - `POST /oauth/token` (`src/lib/oauth/token-service.ts`, 60 requests per 10 minutes per IP): authorization_code runs `redeemCode` in `src/lib/store/oauth.ts`, one statement that locks the unused code (`FOR UPDATE`), checks expiry, client, redirect uri, the S256 challenge of the verifier, resource and that the listener is served, creates the grant and both tokens only when all pass, and marks the code used with the grant id either way; a concurrent replay waits on the lock, then finds the code used with its grant id and revokes that grant. A reused code always revokes the grant it produced. refresh_token rotates (old one revoked in the same statement as the new pair); a revoked refresh token coming back revokes the whole grant. Access tokens are 32 random bytes (base64url), 1 hour; refresh 60 days; only sha256 hashes are stored. `POST /oauth/revoke` (RFC 7009) always answers 200; revoking a refresh token revokes the grant.
- `/account` lists active grants (client, connected, last used) with Disconnect, and shows setup for Claude Code (`claude mcp add --transport http diffcast <origin>/api/mcp`), Cursor (`.cursor/mcp.json`) and Claude desktop and claude.ai (custom connector). `/agents` is the public explainer.
- Generator: `/api/jobs/due` sends `workContext` (unexpired rows, newest first, at most 10; `.default([])` in the contract so an old API still parses). The brief labels projects `private project N`, redacts their names from summaries, merges context packages into the stack and calls the context the strongest signal (`tools/generator/src/work-context.ts`). `checkScript` fails a script whose title, summary, headings, challenges or turns name a project (whole word, case insensitive; the full project and its last path segment when 5 or more characters; never the show name), so the writer retries.
- How to test: `pnpm test` covers every OAuth rule and tool with an in memory store (`src/app/oauth/oauth-flow.test.ts`, real routes and the official SDK client), pure rules (`src/lib/oauth/rules.test.ts`), the metadata fetch against a local server (`src/lib/oauth/clients.test.ts`), the consent wording (`consent-view.test.tsx`), and the real SQL of `redeemCode`, refresh rotation, revocation and session epochs on PGlite with every migration applied (`src/lib/store/oauth.sql.test.ts`, harness `src/test/pglite.ts`, which stands in for `@/lib/db` and supports nested fragments). PGlite runs one statement at a time, so the concurrent replay is checked by the e2e script, which fires 4 exchanges of one code at once and expects one win, three `invalid_grant` and the winning token revoked. End to end against a running app: `node scripts/mcp-e2e-listener.mjs create <cookie-file>`, then `DIFFCAST_E2E_COOKIE=$(cat <cookie-file>) node scripts/mcp-e2e.mjs <base-url>`, then `node scripts/mcp-e2e-listener.mjs delete`. The e2e script posts the consent form the way a browser without JavaScript does (its hidden server action fields plus `decision=allow`). `--discovery-only` runs just the database free discovery steps.

## Design system

- Tokens live on `:root` in `src/app/globals.css` as `light-dark()` pairs, so dark mode follows `prefers-color-scheme` with no `dark:` variants. Tailwind color names: `bg`, `surface`, `sunken`, `fg`, `muted`, `line`, `edge` (control borders, 3:1), `add` and `add-soft` (green: success, additions), `del` and `del-soft` (red: errors, removals), `warn-soft`, `warn-line`. Never use Tailwind palette colors.
- Type: Geist for text, Geist Mono for labels, metadata and code. Sizes `text-display` and `text-title` are fluid. Radius: `rounded-control` (6px) for controls, `rounded-card` (10px) for cards.
- Every interactive control is a UI SDK part (`@ui-sdk/react/*`, skill in `.claude/skills/ui-sdk`; read `node_modules/@ui-sdk/react/docs/llms.txt` first). `@layer ui-sdk;` sits above the Tailwind import and `@ui-sdk/core/web.css` is imported into `layer(components)` and themed through the `--ui-*` tokens. Button variants are data attributes: `data-variant="solid" | "destructive" | "quiet"`, `data-size="lg"`.
- Classes: `.card`, `.table-frame` around `table.data-table`, `.code-chip`, `.honeypot`. The diff motif (a red bar over a longer green bar, `+` and `-` gutters) is the brand mark; keep it to the wordmark, the hero panel and semantic states.
- Trap: the CSS pipeline drops `flex-direction: row` as a default value, so overriding a column flex from `web.css` needs `flex-flow: row wrap`.

## Local database

`scripts/local-db/server.mjs <data dir>` serves Neon's HTTP SQL protocol on 127.0.0.1:4444 from a PGlite database in that directory and applies every migration on start; `scripts/local-db/preload.mjs` rewrites the driver's `https://api.localtest.me/sql` requests to it. Run the app on it with `DATABASE_URL=postgres://local:local@db.localtest.me/diffcast DATABASE_URL_UNPOOLED=<same> NODE_OPTIONS="--import $PWD/scripts/local-db/preload.mjs" pnpm next dev -p <port>` (process env beats `.env.local`). Stripe stays on the test key from `.env.local`; Stripe cannot reach localhost, so relay a real test event by fetching it with the test key, signing it with `Stripe.webhooks.generateTestHeaderString` and a local `STRIPE_WEBHOOK_SECRET`, and posting it to `/api/stripe/webhook`. Use `delivered@resend.dev` as the signup email so the welcome email goes to Resend's test sink. A listener session cookie can be minted as in `scripts/mcp-e2e-listener.mjs`. Used for the DIF-5 end to end run (2026-11-18).
